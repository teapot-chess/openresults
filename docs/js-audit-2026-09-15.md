# Browser-side JavaScript - audit of 2026-09-15

The last area of OpenResults no audit had read. Scope: `assets/js/app.js` and
every inline `<script>` under `lib/openresults_web/`, the Content Security
Policy those scripts run under, and the server output they compare and match
against. Same method and format as OpenPairings'
`docs/js-hooks-audit-2026-09-13.md`.

Line numbers are at `f0fe6bd`, the commit the audit started from.

## How it was checked

- **Read**, all of it.
- **Server side**, with conn tests: `test/openresults_web/page_scripts_test.exs`
  (8 tests; 6 failed against `f0fe6bd`, all pass after `13d833e`; the other
  two are regression guards that already held).
- **In a real browser.** The repository has no JS runner and this audit adds
  no JS dependency, so the real pages were rendered by a throwaway conn test
  (standings, round, team round, projector, index) from both `f0fe6bd` and the
  fix, served from a static local server, and driven in a Chromium tab: typing
  into the search box, and running the refresher's own poll by dispatching
  `visibilitychange`. The static server returns byte-identical HTML on every
  poll, which is exactly the "nothing changed" case. The harness stayed in the
  scratchpad. Before/after results are under each finding.

### F1 - Every poll "updated" the page, even when nothing changed (Medium)

The refresher decided whether to swap by `fresh.innerHTML === live.innerHTML`.
The live region is never the server's markup: the filter bar's script adds
`js-auto` to the form on load, closes the phone disclosure and hides rows. So on
the standings, round and cross-table pages every poll found a "change", every
10 to 20 seconds, per spectator:

- the whole region was replaced (a screen-reader user in browse mode loses
  their place every time; nothing is gained),
- "updated just now" was shown and **announced through `#announcer` on every
  poll**,
- the phone filter panel was closed again (F6) and typed text rows unfiltered (F4).

Browser, `f0fe6bd`, identical server response: 1 swap per poll (2 in 2 polls),
announcer "updated just now". Fixed: `#live-region` carries `data-version`, a
SHA-256 digest of the region's rendered HTML (`Layouts.region_version/1`), only
on a 200. The refresher compares that and updates it after a swap; markup
comparison remains only as a fallback for a response without it. Browser, fix:
0 swaps on an identical response, status hidden; with `data-version` set stale,
exactly 1 swap and "updated just now". Tests: `data-version` equal across two
fresh renders, changes on a new publish, present on the index page.

Why a content digest and not the ETag/snapshot id: the region is what is
swapped, so the region is what must be compared, and the index page has no ETag.

### F2 - The live filter matched the wrong rows (Medium)

`row.querySelectorAll(".name")` read every name in the row. A standings row's
tie-break working (folded `<details>`) names every opponent, so typing "muller"
left Müller **and both players who had played him**. On a round, White's and
Black's names were joined, so "jorg nikola" could match a board across the two.
The scope was `table tbody tr` under the bar's parent, which on a team round
included the matches table: team rows carry no player names and were hidden
(browser, `f0fe6bd`: 3 of 4 match rows hidden typing a player's name).

Fixed: only the first `.scroller` table after the bar, only its own
`:scope > table > tbody > tr`, only `.name`s whose row is that row and not inside
`<details>`, and a board shows when either name matches. Browser, fix: "muller"
leaves 1 row; the team matches table is untouched while the boards table filters.

### F3 - Typing and pressing Enter disagreed (Medium)

The live filter folded accents; the server search (`Filter.name_match?/2`) only
lower-cased. "muller" showed Müller while typing and "No players match" after
Enter. Neither handled word order, so "Ilse De Vos" never found the arbiter's
"De Vos, Ilse" (the fixture's form of every name).

Fixed, both sides the same rule: NFD, combining marks removed, lower case; the
query split on whitespace and commas; every word must be in the name. Tests:
`?q=muller`, `?q=angstrom`, `?q=Jean-Baptiste+De+Smet`, two unrelated words,
and words split between White and Black on a round.

### F4 - A refresh left the search box filled over every row (Medium)

The refresher puts typed text back before `openresults:updated`, but the filter
bar only filtered on `input`, so after a real update the box still said
"muller" over all rows (browser, `f0fe6bd`: 10 of 10 visible). It happens
whenever the reader typed and then moved focus (to a result, a name) - the poll
only waits while focus is in the box.

Fixed: `init` re-applies the filter whenever the box holds text, and treats text
equal to the server's own `q` (`defaultValue`) as already applied. Browser, fix:
1 row visible and the count kept after a forced swap.

### F5 - Filtering while typing made no sound (Medium, accessibility)

Rows were hidden with no announcement and the "12 of 86 players" count stayed
put. Fixed: the count reads "Rows matching: N of M" while the live query differs
from the server's, goes back to the server's sentence when it does not, and the
sentence is announced 600 ms after the last keystroke (once per pause, not per
letter). The template is a `data-live-count` attribute from gettext, translated
nl and fr. "Rows" rather than players/boards keeps it plural-free. Test: the
attribute carries both placeholders.

### F6 - The phone filter panel reopened or closed itself (Low)

The refresher restored only `details[open]` and the filter bar re-closed its
disclosure on every `init` on a narrow screen, so a phone reader who opened
Filters had it snap shut on the next swap. Fixed: open and closed state are both
restored (with a path from the region when no identifying ancestor exists), and
the bar closes the disclosure only on first load. Browser, fix: stays open.

### F7 - The projector rewrote its boards every minute (Low)

Same pattern as F1 on the `<tbody>`: paging sets `hidden` on rows. No visible
blink (rows re-paged at once) but a DOM rewrite and re-measure each minute on a
screen left on for days. Fixed: compared with the last served HTML. Browser:
1 rewrite before, 0 after on an identical response.

### F8 - Polls could overlap, and a redirect was swapped in (Low)

A `visibilitychange` tick could start while the timer's request was out; two
swaps could land in either order. A same-origin redirect (a page moved or
withdrawn) had its region swapped under the old address. Fixed: one request at a
time; `response.redirected` is never swapped.

### F9 - The tournament list search did not fold accents (Low)

"liege" did not find "Liège". Fixed with the same fold.

### F10 - No `script-src` in the CSP (Low, fixed in the 2026-10-19 sweep)

The public CSP is Phoenix's `base-uri 'self'; frame-ancestors 'self'`, rewritten
to `frame-ancestors *` by `OpenResultsWeb.Framing`. There is no `script-src`, so
the inline scripts need neither nonce nor hash - and an HTML injection would run.
None was found: all data goes through HEEx escaping, the four `raw/1` uses wrap
`escaped/1` or the changelog's own Markdown, and every script writes with
`textContent`. A nonce cannot work here: `Plugs.Revalidate` serves cached bodies
to many readers, and a per-response nonce in a shared body is not a nonce. The
scripts are static, so `script-src 'self' 'sha256-...'` is possible, with a test
that recomputes the hashes from rendered pages; left as defence in depth for a
separate change. The admin panel is already `script-src 'none'`.

**Fixed 2026-10-19.** As prescribed: every inline script moved, unchanged,
into `lib/openresults_web/inline_scripts/*.js`; `OpenResultsWeb.InlineScripts`
writes each into its page and hashes the same bytes at compile time, and
`OpenResultsWeb.Plugs.ContentSecurityPolicy` sends `script-src 'self'` with
those hashes, plus `object-src 'none'`, `base-uri 'self'`, `form-action
'self'` and `connect-src 'self'` (`frame-ancestors` still rewritten by
`Framing`). `AccessibilityTest` walks every public page from the router and
recomputes the hash of every inline script it finds against the header that
went out with it. No inline event handler or `javascript:` link existed, so
none had to move.

### F11 - A withdrawn page shows "not updating - connection lost" (Low, not fixed)

A 404 on a poll counts as a network failure. Wrong wording, harmless, and the
alternative sentence needs new copy; left.

### F12 - `app.js` is dead scaffold (Info, not fixed)

Built by `mix assets.build` but never referenced by a page. If it were loaded it
would throw at once (`meta[name='csrf-token']` does not exist) and try to open a
LiveView socket the site does not serve. Removing it touches the esbuild config
and deploy; left for a cleanup.

### F13 - Small leftovers (Info, not fixed)

`IDENTIFYING` lists `data-sort-key`, `data-filter` and `data-standings-reset`,
which nothing renders any more (harmless). The fold, on both sides, does not
turn `Đ`, `Ł` or `ø` into ASCII because Unicode does not decompose them;
consistent between typing and Enter, so no disagreement.

## Checked and found sound

- **No HTML from data.** No `insertAdjacentHTML`, `outerHTML`, `document.write`,
  `eval`, `new Function` or string `setTimeout`. `innerHTML` is written in two
  places, both with the server's own HTML from `fetch(location.href)` - same
  origin by construction, the response parsed with `DOMParser` and only the
  `#live-region` / `#projector-boards tbody` contents taken, into those same
  containers. Scripts inserted through `innerHTML` do not execute; the page's
  own scripts re-wire via `openresults:updated`. The player card adopts a
  parsed `#player-summary` node from a same-origin page. The FIDE lookup builds
  every result with `createElement` + `textContent`; `r.json()` failures reach
  the `.catch`; stale responses are dropped by a request counter.
- **No `postMessage`, `window.open` or redirects built from parameters.** The
  one script navigation is the card's fallback to `link.href`, a
  server-rendered player URL.
- **Storage.** Both `localStorage` accessors are in `try`; no `sessionStorage`.
- **Timers.** The refresher and projector skip work while `document.hidden`;
  the refresher's `setTimeout` loop is a single chain; nothing polls after
  navigation (a full page load ends the document).
- **Listener growth.** Every `document`/`window` listener is added once per page
  load: inline scripts inside the region do not re-run on a swap, so
  `openresults:updated` handlers cannot stack. Element listeners are attached to
  the fresh nodes of each swap and die with the old ones; the `select` listener
  now also carries a `data-auto-submit` guard. Nothing accumulates on a
  projector left running.
- **Query string.** The refresher fetches `location.href`, filters included;
  it skips a poll while focus is in an input, select or textarea, and restores
  typed text otherwise.
- **Error isolation.** Each block is its own IIFE in its own `<script>`, so a
  throw in one cannot stop another; the body script's early `return` (no card
  overlay) cannot trigger because the overlay is in the layout.
- **Focus.** After a swap focus is relocated without scrolling; the card
  returns focus to its opener (relocated if swapped meanwhile); the theme picker
  returns focus to its trigger.
